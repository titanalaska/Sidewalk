# Shift Log Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Crew tap each walk Cleared / Treated / Problem / Checked during a storm; Matt and leads watch every route live; site cards replace the paper sheet.

**Architecture:** Three append-only tabs (`Log`, `Storms`, `Visits`) in the Snow App Sheet. Every state is "the newest row", worked out by one pure module, `shiftlog.js`, that is byte-identical in both repos (like `board.js`). The backend adds five actions; the phone adds a Storm tab that polls only rows after its cursor.

**Tech Stack:** Apps Script (clasp), node `--test` + the vm fake Sheet, browser JS (no build), Playwright over `file://`, api.weather.gov.

**Spec:** `docs/superpowers/specs/2026-10-03-shift-log-design.md` (read it with this plan).

## Global Constraints

- Repos: phone = `Snow-App-repo` (PUBLIC, code only, **no data files**), backend = `snow-app-script` (branch `master`, no remote). Phone work on a new branch `shiftlog` cut from `maps`.
- Rows are **never edited or deleted** in `Log`, `Storms`, `Visits`. Order = `seq` assigned on the server under the script lock; never the phone clock, never array position.
- `by_profile` / `by_name` always come from the token (`a`), never the request body.
- Zone states: sidewalk and `whole` → `cleared | treated | problem`; heated → `checked | problem`; no_touch → none. `problem` needs a non-blank note.
- Storm controls (`start | end | reopen | snowing | stopped | night_on`): admin and lead only.
- Judgment values ship empty: depth, minutes and materials are blank unless typed; never default to 0.
- Poll interval **20 000 ms**, only while the Storm tab is on screen and the document is visible.
- Backend `VERSION = 'shiftlog-1'`; phone `EXPECTED_BACKEND: 'shiftlog-1'`; shell `CACHE_VERSION = 'titan-snow-shell-13'`.
- `lib/*.js` must parse (`test/scripts-parse.test.js`); long edits via the Edit tool, never sed/heredoc.
- Every new guard gets a backend mutation in `test-tools/mutation-check.js`; phone guards are mutated by hand once each and the result noted in the commit message.

## Review Focus

1. **A poll reply and a tap reply carrying the same row** → the walk shows once, at the newer state; never duplicated or flipped back (Task 4 test).
2. **Cursor larger than the tab** (Matt deleted rows by hand in the Sheet) → server answers every row with `reset: true`, phone replaces its copy (Task 2 test).
3. **Phone left open across 9 AM** → the site card files under the shift the *server* computes; a `shift_id` sent by the phone is ignored (Task 3 test).
4. **Session expires mid-poll** → polling stops and sign-in shows, no retry loop (Task 4 test).
5. **Storm ended while a crew screen is open** → the next tap shows "No storm is open" and stays unsaved (Task 4 test).

**Interfaces:**
- Consumes: `CrewTime.shiftDate(iso)`, `CrewTime.shiftId(kind, date)`, `CrewTime.SHIFT_CUTOVER_HOUR` (time.js).
- Produces `CrewShiftLog` (UMD like `history.js`: `factory(require('./time'))` / `root.CrewShiftLog = factory(root.CrewTime)`):
  - `walkKey(siteId, zoneId) -> 'S1|Z4'`
  - `walksFor(siteId, zones) -> [{zone_id, type, name}]` — live `sidewalk`/`heated` zones of that site, by name; if none, `[{zone_id:'whole', type:'sidewalk', name:'Whole site'}]`.
  - `statesFor(type) -> string[]` — `sidewalk`: `['cleared','treated','problem']`; `heated`: `['checked','problem']`; else `[]`.
  - `checkTap({walk, state, note}) -> ''|reason`
  - `stormState(stormRows) -> {storm_id|null, open, snowing}`
  - `shiftFor(iso, stormRows) -> 'night-YYYY-MM-DD'|'day-YYYY-MM-DD'`
  - `walkStates(logRows, stormId) -> {[walkKey]: row}` (newest by `seq`; `state:'none'` rows mean not done)
  - `undoTarget(logRows, stormId, seq) -> {ok:true, row, state} | {ok:false, reason}`
  - `siteDone(siteId, zones, states) -> bool` — every walk of `walksFor` is in `cleared|treated|checked`.
  - `routeProgress(siteIds, zones, states) -> {done, total}`
  - `siteTimes(logRows, siteId, shiftId) -> {start|null, finish|null}` (first/last `at` by `seq`)
  - `visitTotals(visits, siteId, shiftId) -> {cards:[row], minutes:{blower,snowrator,bobcat,sweepster}}` — newest card per `by_key` (the writer's crew id, or `'admin'`; crew ids are already on the crew's post, so this is safe on every phone); minutes summed over those cards, a blank minute adds nothing; a key with no minutes on any card is `null`, not 0.
