# Sidewalk in Spanish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The crew screens of Sidewalk read in Spanish on a phone whose EN / ES switch is set to ES, with nothing a person typed and nothing that leaves the app translated.

**Architecture:** One new file, `lib/es.js`, holds Groundwork's DOM translation engine (dictionary, longest-first word-bounded alternation, text-node walk plus four attributes, a `WeakMap` of originals, a `MutationObserver`) and the dictionary itself. The header gets EN / ES buttons; `app.js` reads the `snow-lang` key (falling back once to `wolf-lang`), paints the buttons, and starts the engine after the first render. Every place a person's words render gets `data-no-es`. No render code changes anywhere else.

**Tech Stack:** Vanilla JS (ES5 style, IIFE modules exporting through `module.exports` and `window.*` like `lib/geo.js`), node `--test` for pure logic, Playwright over `file://` for the page.

**Spec:** `docs/superpowers/specs/2026-10-09-spanish-design.md`

## Global Constraints

- The localStorage key is `snow-lang`, values `"en"` or `"es"`; anything else reads as English. Once named it is never renamed.
- First read with no `snow-lang`: read `wolf-lang`; if it is `"en"` or `"es"`, use it and write it to `snow-lang`.
- tú throughout, never usted. Mexican Spanish, Groundwork's vocabulary.
- Display only: site names, addresses, notes, materials lines, zone names, people's names, `#bt_text` and the crew post are never translated. The API never receives a Spanish word.
- Crew screens only get dictionary rows: sign-in and access screens, the tabs, Storm, Tonight, Routes, Sites, the site map page (legend, photo switch, warnings), the own roster card, `lib/api.js` messages, the weather hint, toasts and errors from those screens.
- Tests on translated text assert `toBeVisible` on the Spanish and `toBeHidden` (or `toHaveCount(0)`) on the English; never `toContainText` alone.
- Expected values in tests are worked out from the source on paper, never pasted from a run.
- No backend change; `EXPECTED_BACKEND` stays `curbs-1`. Shell: `lib/es.js` joins `SHELL` and `CACHE_VERSION` becomes `titan-snow-shell-37` in the same commit as the file, with `test/sw.spec.js` and `test/manifest.test.js` updated.
- Nothing is deployed by this plan; Matt ships with `/sidewalk-deploy` after one crew member has read the Storm tab in ES on a test phone.

## Review Focus

1. A short key inside a longer English phrase: "Back" must not turn the `#verwarn` banner "Backend out of date…" into "Atrásend…". Pinned in Task 1 (`test/es.test.js`, word boundary).
2. A text node with a trailing space before a bold child ("Tonight: <b>…</b>"): the leading/trailing whitespace must survive translation or the words run together. Pinned in Task 1 (`translateString` keeps lead/trail) and Task 3 (Tonight in ES).
3. Switching ES twice, or ES then EN then ES, must not translate already-Spanish text again or lose the English originals. Pinned in Task 2.
4. A toast or walk row that arrives after the switch (the observer path) must be Spanish, and the observer must not re-enter on its own writes. Pinned in Task 3.
5. `lib/es.js` missing from a stale shell cache: the app must still sign in and run in English. Pinned in Task 5.

**Files:**
- Create: `lib/es.js`

**Interfaces:**
- Produces: `SnowEs` (IIFE result, `module.exports = SnowEs` and `window.SnowEs = SnowEs` exactly as `lib/geo.js` does) with
  - `ES` — object, English key → Spanish value
  - `ES_RULES` — array of `[RegExp, string | function]`, applied after the dictionary pass, in order
  - `translateString(v: string) -> string` — pure; collapses inner whitespace for matching, keeps one leading / trailing space if the input had whitespace there; returns `v` unchanged when nothing matched
  - `lang() -> 'en' | 'es'`
  - `setLang(next: string) -> void` — stores `snow-lang`, sets `document.documentElement.lang`, paints the buttons, translates the body (ES) or restores English (EN); never reloads, never re-renders
  - `translateNode(root: Node) -> void`, `restoreEnglish() -> void`
  - `start(wrapId: string) -> void` — reads the key (with the `wolf-lang` fallback), wires the buttons in `#wrapId`, paints them, translates `document.body` if ES, starts the observer
  - `readLangKey() -> 'en' | 'es'` — pure except for localStorage reads/writes; exposed for the Task 2 tests
